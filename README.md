# 디노테스트 웹 버전 (1단계)

터미널 스크립트를 브라우저에서 쓸 수 있게 옮긴 것입니다.
파이썬을 모르는 사람도 링크만 열면 쓸 수 있습니다.

```
dino/
├── app.py                        화면 (Streamlit)
├── dino_core.py                  계산 로직 (print/input 없음)
├── requirements.txt
├── .gitignore
└── .streamlit/
    └── secrets.toml.example      키 넣는 자리
```

---

## 1. 먼저 할 일 — 키 재발급

기존 코드에 DART 키와 네이버 Client ID/Secret 이 평문으로 들어 있었습니다.
**세 개 모두 폐기하고 새로 발급받으세요.** 새 키는 코드가 아니라 아래 파일에만 넣습니다.

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
```

`.streamlit/secrets.toml` 을 열어 값을 채웁니다.
이 파일은 `.gitignore` 에 이미 들어 있어 깃허브에 올라가지 않습니다.

---

## 2. 내 컴퓨터에서 실행

```bash
cd dino
python -m venv .venv
source .venv/bin/activate        # 윈도우: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

브라우저가 `http://localhost:8501` 로 열립니다.

---

## 3. 인터넷에 올리기 (무료)

1. 이 폴더를 깃허브 **비공개** 저장소로 올립니다 (`secrets.toml` 은 자동 제외됨).
2. share.streamlit.io 에서 저장소를 연결합니다.
3. 앱 설정의 **Secrets** 칸에 `secrets.toml` 내용을 그대로 붙여넣습니다.

배포하면 `https://…streamlit.app` 주소가 나오고, 그 링크만 있으면 누구나 접속합니다.

---

## 4. 원본에서 바뀐 점

| 항목 | 전 | 후 |
|---|---|---|
| API 키 | 코드에 직접 | `secrets.toml` / 환경변수 |
| 입출력 | `input()` / `print()` | 웹 폼 + 표 + 진행률 막대 |
| 계산과 출력 | `print_*` 함수 안에서 섞임 | `dino_core.py` 는 값만 반환, `app.py` 가 표시 |
| 기준 데이터 | 실행할 때마다 DART·KRX 재다운로드 | 한 번 받아 캐시, 사이드바 버튼으로 갱신 |
| 주가 출처 | yfinance 먼저 | **pykrx → 네이버 → yfinance** 순 |
| KRX 목록 | KIND 다운로드만 | 실패 시 pykrx 로 대체 |
| CSV | 서버 디스크에 저장 | 화면에서 내려받기 버튼 |

### 주가 출처를 바꾼 이유

Yahoo 는 데이터센터 IP를 강하게 제한합니다. 내 PC 에서 잘 돌던 코드가
클라우드에 올리면 조용히 빈 데이터만 돌려주는 일이 흔합니다.
국내 종목은 pykrx 가 훨씬 안정적이라 1순위로 두고, 나머지는 예비 경로로 남겼습니다.

### 원본에 있던 문제 하나

`get_historical_disclosures` 가 DART `list.json` 을 부를 때 `pblntf_ty="A"`(정기공시)를
넣고 있었습니다. 그런데 점수를 매기는 항목 — `단일판매ㆍ공급계약체결`, `유상증자결정`,
`자기주식취득결정` — 은 전부 정기공시가 아닙니다.
그래서 조회 결과에 해당 항목이 들어올 수 없었고, **재료점수가 사실상 항상 2점으로 고정**되어
기업점수 20점 중 5점이 죽어 있었습니다.

지금은 공시 조회에서 유형 필터를 빼서 전체 공시가 들어옵니다.
백테스트 점수 분포가 원본과 달라 보이면 이 수정 때문입니다.

---

## 5. 이 버전의 한계

- 브라우저를 닫으면 진행 중인 백테스트가 멈춥니다. (Streamlit 구조상 그렇습니다)
- 여러 명이 동시에 백테스트를 돌리면 DART 일일 한도가 빠르게 소진됩니다.
- 생존편향이 그대로 남아 있습니다. 현재 상장사 목록을 과거로 되돌리는 방식이라
  이미 상장폐지된 종목이 표본에서 빠집니다.

**혼자 또는 몇 명이 쓰는 용도**로는 충분합니다.
불특정 다수에게 공개할 계획이라면 2단계로 넘어가야 합니다.

---

## 6. 2단계로 넘어갈 때

핵심은 **실시간 계산을 없애는 것**입니다.

- 매일 새벽 서버가 전 종목 점수를 계산해 DB(SQLite/Postgres)에 저장
- 웹은 DB 조회만 — 즉시 뜨고, 접속자가 늘어도 API 호출은 0회
- 백테스트도 미리 돌려둔 결과를 보여주는 형태

이렇게 하면 위 세 가지 한계 중 앞의 두 개가 한꺼번에 해결됩니다.
`dino_core.py` 는 그대로 재사용할 수 있습니다 — 부르는 쪽만 바뀝니다.

---

불특정 다수에게 종목 선별 결과를 제공하는 서비스는 자본시장법상
**유사투자자문업 신고** 대상이 될 수 있습니다. 무료인지 유료인지, 공개 범위가 어디까지인지에
따라 판단이 달라지므로, 외부 공개 전에 금융감독원이나 전문가에게 확인해 보세요.
저는 법률 전문가가 아니라 확정적으로 말씀드리기 어렵습니다.
